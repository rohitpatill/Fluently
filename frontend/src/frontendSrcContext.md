# frontendSrcContext.md — scope: `frontend/src/`

Parent: [../frontendContext.md](../frontendContext.md). Child: [components/frontendSrcComponentsContext.md](components/frontendSrcComponentsContext.md).

| File | Purpose |
|---|---|
| `main.jsx` | React root: QueryClientProvider (retry 1, no refetchOnWindowFocus) + sonner `<Toaster>` + Fontsource imports + index.css. Also the **native bootstrap**: `initNativeApp()`, then `loadToken()` **awaited BEFORE the first render** (so the initial `/api/auth/me` already carries the bearer token and a logged-in user isn't flashed the login screen), then `initAuthDeepLink(...)` whose callback calls **`queryClient.resetQueries()`** — deliberately `reset`, NOT `invalidate`, because `['me']` sits in an ERROR state from the pre-login 401 and uses `retry:false`, which an invalidate won't refetch. All inert on web. |
| `App.jsx` | Shell + gating order: health check (error ⇒ full-screen retry, whose message now reports the **actual** `VITE_API_URL` instead of a hardcoded `localhost:8000` — it lied in every non-local build) → **auth gate** (`useMe`; 401/no session ⇒ `<Login>`) → onboarding gate (`me.has_persona` false ⇒ `<Onboarding>`) → **model-config gate** (`me.has_key` false ⇒ standalone `<BrainStep>`, for users who set a persona before the BYO-key feature) → responsive rail/bottom-nav + AnimatePresence view switch: 'chat' \| 'words' \| 'memory' \| 'settings'. After onboarding OR the standalone brain-gate completes, view is set to **'words'**. Derives the **active persona** from `usePersonas` → passes `personaName`/`personaAvatar`/`personaId` to Rail/Chat (so avatars + persona-scoped conversation cache follow the active companion). Passes `me` to Rail/SettingsView. Persona/identity/personas queries are `enabled` only once authenticated. Uses `useKeyboardInset`: when the mobile soft keyboard opens, hides the bottom nav (`hidden` prop to Rail) + drops its reserved `pb-[76px]`. Also mounts the **Fluently voice assistant**: a draggable `<AssistantFab>` (shown app-wide once `useAssistantStatus().available`, hidden while the keyboard is open) + a one-time first-run hint (localStorage `fluently.assistantHintSeen`) + `<AssistantOverlay>` (passed `tab={view}`); `handleAssistantAction(name)` invalidates the affected caches (words/dashboard, personas/me, or me/assistant-status) so assistant actions show up without a refresh. |
| `index.css` | `@import "tailwindcss"` + `@theme` design tokens: color palette (accent/bg/surface/border/muted/amber/green/red), fonts (sans=Schibsted Grotesk, serif=Newsreader, mono=JetBrains Mono), radii, shadows (soft/card/accent), keyframes (msgIn/chipPop/dotPulse/fadeIn/shimmer/**skeletonSweep**). Plus scrollbar styling, `.font-serif-italic` helper, `.skeleton-shimmer` (calm gradient-sweep placeholder, `--animate-skeleton`), and a **`html.capacitor-native body`** safe-area rule (`env(safe-area-inset-*)`) — Capacitor 8 renders edge-to-edge, so the app pads for the status/nav bars; the class is never added on the website, so web layout is byte-for-byte unchanged. ALL new tokens go here. |
| `api.js` | Fetch wrapper (`ApiError` with status; friendly network-down message) + one exported function per backend endpoint. Base URL comes from `import.meta.env.VITE_API_URL` (Vite env, baked at build — set in `frontend/.env` locally / hosting dashboard in prod; falls back to nothing if unset, so it MUST be configured). NO hardcoded localhost anymore. **All requests send `credentials: 'include'`** (the cross-origin session cookie). Auth: `getMe()` (GET /api/auth/me), `logout()` (POST /api/auth/logout), `loginWithGoogle()` (full-page redirect to `${BASE_URL}/api/auth/google/login`). Words: `setWordNote(id, note)`. Memory: `appendMemoryLine`, `editMemory(...)`, `putMemoryRaw`, `submitOnboarding(name, about)`. Model (BYO key): `getModelTiers`, `getModelStatus`, `setModelKey(apiKey, tier)` (verify+store), `setModelTier(tier)`. Personas: `listPersonas`, `createPersona`, `editPersona(id,data)`, `setPersonaAvatar(id,url)`, `activatePersona(id)`, `deletePersona(id)`, `getPersonaCatalog`, `usePersonaFromCatalog(catalogId)` (Discover copy). Voice: `getVoices`, `getVoiceStatus`, `voiceSocketUrl(convId)` (derives `ws://` from the http base). Assistant: `getAssistantStatus`, `assistantSocketUrl(tab)` (ws URL for the in-app Fluently helper, carries the current screen). **NATIVE AUTH:** `request()` adds `Authorization: Bearer <token>` when `authToken.getToken()` is set (native only — null on web, so the cookie still authenticates); `withSocketAuth()` appends **`?token=`** to both socket URLs because the browser WebSocket API cannot send headers; `loginWithGoogle()` branches — web does the usual full-page redirect, native opens `…/google/login?native=1` in the SYSTEM browser via `@capacitor/browser` (Google forbids OAuth in WebViews); `logout()` also clears the stored token. |
| `platform.js` | **The single web-vs-native seam** (Capacitor). `isNativeApp()`/`isWeb()`/`platform()`; `initNativeApp()` (called once from `main.jsx`; tags `<html class="capacitor-native">` so the safe-area CSS applies in the app only); **`initAuthDeepLink(onAuthenticated)`** — registers the `@capacitor/app` `appUrlOpen` listener that catches `com.fluently.app://auth?token=…` after system-browser login, stores the token, closes the browser tab. ALL of it is a no-op on the website. New native concerns belong HERE, not inline in components. |
| `authToken.js` | Native session-token store (`@capacitor/preferences`, cached in memory so `api.js` can read it synchronously). `getToken`/`loadToken`/`setToken`/`clearToken`. Exists because the app's WebView cannot use the HttpOnly session cookie — see `android/frontendAndroidContext.md` §6. No-op / always-null on web. |
| `utils.js` | `relativeTime`, `formatThreadTime`, `nowClockLabel`, `parsePersonaName` (multiline `Name: X` from persona.md), `parsePersonaRelation` (`Relation to user:`), `parseIdentityName` (`Name: X.` from identity entry line), `initial`. |
| `hooks/useApi.js` | TanStack Query hooks: `useHealth` (15s poll), `useMe` (`retry:false` so a 401 resolves fast to "logged out"), `usePersonaMemory({enabled})`, `useConversations`, `useMessages(id)`, `useWords`, `useDashboardStats`, `useWordEvents(id, enabled)`, `useMemoryFile(file, {enabled})`, `useModelTiers({enabled})` (staleTime Infinity), `usePersonas({enabled})`, `usePersonaCatalog({enabled})` (staleTime Infinity — Discover catalogue is static), `useVoiceStatus({enabled})` (is voice available for this user), `useVoices({enabled})` (staleTime Infinity — voice catalogue for the picker), `useAssistantStatus({enabled})` (is the in-app Fluently voice assistant available — same key/tier gate as voice). Query keys: ['health'], ['me'] (carries `has_key`/`tier`), ['memory', file], **['conversations', personaId]** (persona-scoped so switching companion never flashes the old list; bare-prefix invalidation still refreshes all), ['messages', id], ['words'], ['dashboard'], ['word-events', id], ['model-tiers'], ['personas'], ['persona-catalog'], ['voice-status'], ['voices'], ['assistant-status']. |
| `hooks/useKeyboardInset.js` | `useKeyboardInset()` → `{ inset, open }` via the `VisualViewport` API — measures mobile soft-keyboard height. Stays `{0,false}` on desktop/no-keyboard, so callers never affect the laptop layout. Used by App (hide nav) + Chat (pad composer above keyboard). |
| `hooks/useDevMode.js` | `useDevMode()` → `[enabled, toggle]`, localStorage-backed (key `fluently.devMode`), off by default. NOT server state (client-only). Syncs across components in-tab via a custom `fluently:devmode` window event + cross-tab via `storage`. `getDevMode()` helper for a one-off read. |
| `hooks/useVoiceSession.js` | `useVoiceSession(conversationId)` — the whole real-time voice client (used by `VoiceOverlay`). Owns mic capture (16kHz mono Int16 PCM via an inline-blob AudioWorklet) → WebSocket (`api.voiceSocketUrl`) → 24kHz PCM playback queue (gapless, barge-in safe on `interrupted`). Returns declarative state (`status`/`error`/`speaking`/`listening`/`inputText`/`outputText`/`scores`) + `start()`/`stop()`/`dismissScore()`. All audio in refs so re-renders never restart it. |
| `hooks/useAssistantSession.js` | `useAssistantSession(tab)` — the real-time voice client for the Fluently in-app assistant (trimmed sibling of `useVoiceSession`): same 16k mic-in / 24k playback duplex over the `/api/assistant/ws` socket, but ephemeral (no scores, no conversation) — surfaces `actions` (a tool ran) instead of `scores`. `tab` (current screen) is sent to the backend. |
| `components/` | All screens + shared pieces. See child context file. |

Invalidation convention: after a chat turn invalidate messages/conversations/words/dashboard/memory (the agent may have changed any of them); after word/memory mutations invalidate their own keys + dashboard.
